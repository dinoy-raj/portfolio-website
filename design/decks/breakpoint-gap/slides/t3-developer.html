Now let’s move to the developer side. The first responsibility is to stop assuming the app will always run in one orientation or one fixed window size. Second, we need to preserve state.

In Compose, rememberSaveable is useful for small UI state, while ViewModels help us retain screen state across configuration changes. For more important data, we should rely on repositories and persistent storage.

Third, we must test combinations of configuration changes. Don’t just test folding and unfolding on their own: try resizing, rotating and folding in different sequences. We should also base layout decisions on the current window size rather than hardcoding device-specific logic.

And finally, we need to understand multi-window lifecycle behaviour, and support keyboard, mouse and stylus input.
